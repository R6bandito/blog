#### 全局数据结构/静态局部数据结构/普通局部数据结构分别存储在程序的哪些段中？

在进行区分之前，我们先来看看在嵌入式C语言程序中都有哪些核心的内存段划分：

| 段名        | 存放内容                                                     | 物理属性                         | 典型例子                                                     |
| :---------- | :----------------------------------------------------------- | :------------------------------- | :----------------------------------------------------------- |
| **.text**   | **代码段**：所有可执行指令、函数体。                         | **Flash（只读）**                | if、while、函数调用等等。                                    |
| **.rodata** | **只读数据段**：常量、字符串字面量。                         | **Flash（只读）**                | `const char *p = "Hello";` 中的字符串 `"Hello"`。            |
| **.data**   | **已初始化读写数据**：全局/静态变量，且有非零初值。          | **Flash存初值，启动时拷贝到RAM** | `int a = 5;` 中的 `5` 存在Flash，变量 `a` 在RAM。            |
| **.bss**    | **零初始化数据**：全局/静态变量，无初值或初值为0。           | **RAM（无Flash占用）**           | `int b;` 或 `static int c = 0;`。启动时由 `__main` 循环清零。 |
| **Stack**   | **栈（由编译器管理）**：局部变量、函数调用现场（返回地址、寄存器）。 | **RAM**                          | `uint8_t temp;`（定义在函数内部的）。                        |
| **Heap**    | **堆（由用户管理）**：动态分配的内存。                       | **RAM**                          | `malloc(size)` 申请的空间。**注意**：如果工程没用到标准 `malloc`，这个段通常很小甚至为0。 |

- 对于**全局数据结构**：这里要考虑是否初始化为0。看下面的例子：

```c
uint8_t g_verA;
uint8_t g_verB = 50;
static uint16_t g_init = 100;
```

三个变量均开辟在全局数据区，`g_verA` 默认初始化为0，`g_verB` 和 `g_init` 都进行了对应的初始化。对于 `g_verA`，由于没有进行显示初始化，因此被放在了 .bss 段，上电后由 __main 进行清零操作，并且在 Flash 中零占用；

`g_verB` 和 `g_init` 进行了显式初始化，因此被放入 .data 段中（这里要注意：被放入.data中的只是变量本身，初始化数据是被放入了 flash 中的）。系统上电后，__main 会将 flash 中的对应初始化数据拷贝到 .data 中对应的位置。这也是为什么我们的全局变量能够一进入程序就已经被赋予一个初始化值的原因。

- 对于**普通局部数据结构**：是统一放在函数调用栈中的。

```c
void 
funcA( void )
{
	struct test myTestStructure;
    // ....
}
```

`myTestStructure` 这个结构我们是在函数局部空间进行定义的，因此其被压栈存入到函数栈中。只在当前的作用域有效，一旦函数运行周期结束出栈返回，这个变量的内存空间也随即跟着被销毁了。

由于栈大小是固定且通常比较小，因此不要在局部定义大型数据结构（例如大数组或大型结构体），注意堤防栈溢出。

- **静态局部数据结构**：前面我们说过，static 修饰局部数据结构时不改变其作用域，只规定其生命周期。

```c
void 
funcA( void )
{
	static struct test myTestStructure;
    // ....
}
```

此处，`myTestStructure` 虽然定义语句在局部，但是由于 static 的修饰，其真正的内存空间位置是被放在了 .bss 段(未显式进行初始化，因此默认初始化为0)。当程序流程进入 funcA 时，不会压栈 `myTestStructure`，而是从 RAM 中直接读出该变量，操作完毕后 funcA 返回，`myTestStructure` 依然有效。



这里要强调一点：.bss 和 .data 段一大区别就是是否在 flash 中有占用。.data段的数据在上电时需要来自 flash 中的初始化值，而 .bss 不需要，因此 .data 在 Flash 中和 RAM 中是双份空间占用！
